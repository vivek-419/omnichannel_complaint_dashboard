## 3. 🎯 Defense: Anticipated Evaluator Q&A

### Q1: *"How is the architecture designed to scale on AWS for 100,000+ complaints?"*
> **Answer:** *"Sir, the system is designed for **AWS ECS Fargate** with multi-AZ autoscaling behind an **Application Load Balancer (ALB)**. Static assets are served via **AWS CloudFront CDN**, while database persistence uses **AWS RDS PostgreSQL** with read replicas or **Amazon DynamoDB** with Global Secondary Indexes for single-digit millisecond reads at any scale."*

### Q2: *"How does duplicate compensation prevention work in the Digital Wallet?"*
> **Answer:** *"Every compensation voucher generated by `walletStore.js` is tied to the unique `ticketId`. When an agent attempts to issue compensation, the engine checks `wallet.vouchers.some(v => v.ticketId === ticketId)`. If a voucher already exists for that ticket, the request is rejected with a 400 Bad Request error, preventing duplicate loyalty payouts."*

### Q3: *"How does the SLA escalation engine work in the background?"*
> **Answer:** *"The backend runs a lightweight 20-second non-blocking background poller in `notificationEngine.js`. When a ticket crosses 75% of its SLA deadline, it generates a `DEADLINE_APPROACHING` in-app warning. If the deadline passes without resolution, the engine automatically upgrades the status to `Escalated`, highlights it in red on the dashboard, and dispatches an automated email notification via `nodemailer` / Amazon SES."*

### Q4: *"What happens if the Gemini AI API is offline or has no internet connection?"*
> **Answer:** *"We designed the AI engine in `aiService.js` with a dual-tier architecture. If `GEMINI_API_KEY` is present and active, it calls Google Gemini 1.5 Flash. If the API key is not configured or an external network failure occurs, the system automatically falls back to our local rule-based Contextual AI Engine, ensuring 100% offline uptime and zero service interruption."*
